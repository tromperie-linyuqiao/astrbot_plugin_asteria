# Asteria 工作台结构与来源

陪伴和记忆页面由 Asteria 自身服务提供，正常运行不需要另行安装或启用旧 Private Companion、Memory Companion。宿主仍为 AstrBot。

## 本次重构

- 原陪伴与记忆的单体脚本已拆成按功能维护的 ES modules；app.js 只负责启动。状态集中在各页的 workspace/state.js，页面初始化由 workspace/startup.js 负责。
- workspace/page-runtime.js 是 Asteria 的页面身份、官方 Page 桥接、有限服务请求和统一页头实现。workspace/client.js 只把该页现有业务调用接到 Asteria 陪伴或记忆服务。POST 不探测路由别名、不自动重试。
- 共同实现维护在 tools/build_workspace_assets.cjs，可在插件目录执行 node tools/build_workspace_assets.cjs . 重建。AstrBot 资源令牌限制在单个页面，因此两页各带一份相同的运行实现；不是两个独立维护版本。
- 陪伴的穿搭预览、字体设置、模型分配和 QQ 面板使用显式模块导入，不再通过其他插件命名的 window 全局对象接线。
- 页面仍使用现有业务接口、数据与字段标识。重构没有新建记忆库、发送器、后台任务或外部插件执行者，也没有改变旧数据目录的选择规则。

## 继承范围

这不是从零重写所有视图。部分记忆管理、陪伴设置、列表、表单、动画和展示样式源于历史导入的 Memory Companion 与 Private Companion 工作台；本次把这些保留的视图逻辑接入 Asteria 的模块边界。页面来源说明、源码来源索引以及已有作者和许可声明继续保留，不把继承代码声称为全原创。

core/living/native_pc_business/SOURCE-MANIFEST.json 保留受约束业务的原来源。本次未修改这些业务文件或放宽守卫。native、历史配置键和兼容目录名本身不表示当前仍由外部插件执行。

## 日常答复

对明确询问角色今日事项、活动完成情况或缺正文文章的短问题，Asteria 重新读取当前已授权日常投影，输出有来源的状态答复，并同步普通聊天历史。只有计划时不推断做了或没做；无原文时不补写原文内容。此路径是有界问题匹配，普通聊天及已经提供正文的讨论仍走原回复流程。它不是完整语义理解，也不证明所有模型回复都不会编造。

## 验证与限制

官方 SDK 的静态模块重写和每页资源令牌用于加载各功能模块。页面在宿主沙盒、真实子桥接和原父窗口动作处理器下进行隔离验证；数据、接口结果和故障是有限夹具。维护操作保留原确认、输入保留和未知结果边界。

模块拆分改善维护边界，不声称已减少所有下载量、完成全部无障碍认证或由代理验收手机。原资料、库、角色、配置及自主生活额度不因本次重构而重建。
